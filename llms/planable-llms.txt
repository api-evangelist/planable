## Authentication

- REST: opaque bearer tokens prefixed `pln_`, minted in Company settings -> API tokens by a company
  Owner or Administrator. Two scopes: `read` and `write` (write implies read). Tokens can be restricted
  to specific workspaces and given an expiry from 30 days to Never. Maximum 10 active tokens per company.
- MCP: OAuth 2.0 authorization code + PKCE (S256) with dynamic client registration at
  https://mcp.planable.io/oauth/register. Six scopes: read, approve, edit, publish, analyze, engage.
  Sessions expire after 8 hours of inactivity (auto-refresh); authorization lasts 180 days.

## Runtime semantics an agent needs

- Base URL: `https://api.planable.io/api/v1`. Versioned by URL path; only v1 is served.
- `workspaceId` is a required query parameter on most collection operations — workspace is the scoping key.
- Pagination: `limit` (default 20, max 100) + `offset`; one operation uses `cursor` with `pagination.nextCursor`.
- Rate limits per token: 600 GET/minute, 120 write/minute, Redis sliding window. Every response carries
  `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`. No `Retry-After`. Exhaustion is 429 / `RATE_LIMITED`.
- Errors are vendor JSON, not RFC 9457: `{"error":{"code","message","requestId"}}` with a closed 10-value
  code enum: VALIDATION_ERROR, UNAUTHORIZED, FORBIDDEN, NOT_FOUND, METHOD_NOT_ALLOWED, RATE_LIMITED,
  POST_ALREADY_PUBLISHED, PUBLISHING_IN_PROGRESS, WORKSPACE_LIMIT_REACHED, INTERNAL.
- No Idempotency-Key header. Four operations publish natural-key idempotent semantics: POST and DELETE
  /posts/{id}/share, POST /pages/{id}/competitors, POST /keywords. Treat every other write as non-idempotent.
- Published posts are immutable — editing one returns POST_ALREADY_PUBLISHED.
- Posts created via API or MCP land as DRAFTS and pass through the normal approval flow. If a workspace
  has auto-publish-on-approval enabled, an API-created post publishes once approved.
- Grouped cross-platform posts are created by passing multiple `pageIds` to a single POST /posts.
- Metrics and social-listening syncs are trigger-then-poll, not webhook-driven. There are no webhooks.
- The spec declares no operationId on any operation; identify operations by METHOD + path.

## Plans and limits

- [Pricing](https://planable.io/pricing/): Free (50 lifetime posts), Basic, Pro, Enterprise.
  Analytics and Social Inbox are paid add-ons purchased per workspace.
- Public API token generation requires Pro or Enterprise. MCP is available on all plans.
- Analytics operations and analytics MCP tools require the Analytics add-on on the workspace.
- Post volume caps by plan: Basic 60/workspace/month, Pro 150/workspace/month, Enterprise unlimited.
  Posts created via the API count against these caps.
